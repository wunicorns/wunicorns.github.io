Agent Engineering · 2026 Field Notes

모델이 아니라

차이를 만든다.

프런티어 모델들의 벤치마크 점수가 수렴한 2026년, 성능의 차이는 모델 선택이 아니라 모델을 둘러싼 시스템에서 난다. 프롬프트 → 컨텍스트 → 하네스로 이동해 온 설계의 초점을, LLM 구조·서브에이전트·루프·메모리·검증 관점에서 정리한다.

2022–2024Prompt

작업 단위 = 한 메시지. 역할·지시·형식·예시를 한 턴 안에서 다듬는다.

2025Context

작업 단위 = 창에 무엇을 넣는가. 유한한 "주의 예산"에 맞춰 문서·도구·메모리·이전 턴을 큐레이션한다.

2026Harness

작업 단위 = 모델을 둘러싼 시스템. 규칙·도구·검증·위임을 영속 구조로 쌓는다. Agent = Model + Harness.

01

LLM 구조

에이전트의 심장은 여전히 디코더 트랜스포머다. 중요한 건 그 한계를 아는 것.

  • 디코더 트랜스포머 — 다음 토큰을 자기회귀로 예측. 모든 "추론"은 이 한 메커니즘 위에서 일어난다.
  • 컨텍스트 창 = 유한한 주의 예산 — 창이 길어도 토큰이 많아질수록 주의가 희석된다("lost in the middle"). 길이는 자원이지 공짜가 아니다.
  • 토크나이저 — 한국어·코드는 토큰 효율이 영어보다 낮다. 비용·지연·창 점유가 언어마다 다르다.
  • 추론(thinking) 토큰 — 답 이전에 사고를 토큰으로 "펼치면" 어려운 과제 정확도가 오른다. 대신 토큰·지연을 쓴다.
  • 도구 호출 — 모델은 함수 스키마를 받고 호출을 생성할 뿐, 실행은 하네스가 한다. 모델의 세계 접점은 전부 이 경계를 지난다.
설계 함의: 모델은 상태가 없다. 기억·도구·검증·지속성은 전부 바깥(하네스)에서 온다. "더 똑똑한 모델"보다 "더 좋은 창 구성"이 먼저다.

03

서브에이전트

Orchestrator-Workers — 런타임에 계획을 세우고, 독립 하위작업을 전문 작업자에 위임하고, 요약만 합친다.

쓸 때 / 쓰지 말 때

  • 쓴다 — 하위작업 수가 입력에 따라 달라질 때(예: 파일 수가 요청마다 다른 코딩 과제).
  • 쓰지 않는다 — 잘 좁힌 단일 에이전트로 끝나면 그걸 쓴다. 작업자마다 LLM 호출의 지연·비용·실패가 붙는다. 기본값은 "쓰지 않음".

설계 규칙

  • 컨텍스트 격리가 핵심 — 작업자는 자기 창에서 돌고 요약만 반환한다. 전체 로그를 올리면 오케스트레이터 창이 넘쳐 멈춘다. 다시 전문을 읽기 시작하면 격리가 깨진 것.
  • 한 작업자 = 한 책임 — 한 구절로 역할을 못 적으면 쪼갠다.
  • 원샷 — 작업자는 받은 범위만 처리하고 끝. 오케스트레이터로 되돌아 호출하지 않는다.
  • 얕게 — 중첩은 2단계가 실용적 상한. 각 호출에 타임아웃·실패 처리.
  • 강한 오케스트레이터 + 작은 작업자 — 계획·종합은 큰 모델, 좁은 작업은 작은 모델.
  • 주 실패 모드는 작업자가 아니라 계획 — 틀린 계획이 모든 작업자로 번진다. 출력이 이상하면 계획부터 본다(계획·디스패치·요약을 로깅).
04

루프 엔지니어링

에이전트를 "스스로 도는 루프"로 만든다 — 관찰·계획·실행·검증·학습이 게이트로 묶인 순환.

Task→Plan→Act→Verify (gate)→Evaluate→Learn↺
  • 게이트가 제어한다 — 다음 단계로 넘어갈지는 모델의 판단이 아니라 검증 결과(테스트·오라클·리뷰 통과)가 정한다. 통과 못 한 산출물은 넘기지 않는다.
  • 실패는 학습 데이터 — 실패를 지우지 말고 기록·분석해 다음 전략으로 재시도. 같은 실수가 규칙/도구로 굳는다(하네스가 깊어지는 통로).
  • eval 주도 — 바이브가 아니라 측정으로 전진. 고정 평가셋 + 회귀 + fitness로 전략 변화를 승격/기각.
  • DAG 오케스트레이션 — 제어 흐름(다음 노드·재시도·롤백)을 모델에 맡기지 않고 그래프로 고정하면 재현성이 생긴다.
  • 정지 조건 — 무한 루프 방지: 재시도 상한, 비용/토큰 예산, 되돌릴 수 없는 작업 앞에서의 사람 확인.
성숙도 신호: "프롬프트를 고친다"에서 "루프와 평가를 고친다"로 작업이 옮겨가면, 그 팀은 harness 시대에 들어선 것이다.
05

메모리 아키텍처

모델은 상태가 없다. 지속성은 계층으로 설계한다.

계층담는 것수명 / 위치
Short-term현재 작업 컨텍스트·노드·재시도 횟수세션/상태 파일
Episodic성공·실패 사례(노드·전략·원인·수정)append 로그
Semantic검증된 장기 지식·규칙검증 후 기록
Evolution전략 버전과 성능(fitness)사이클마다
메모리는 "대화 기록 저장"이 아니라 다음 세션의 행동을 바꾸는 교정이다. 재로딩되는 규칙 + 인덱스가 핵심. 저장 데이터는 지시가 아니라 데이터로 다룬다(주입 방어).
06

MCP · 도구 계층

Model Context Protocol — 모델↔도구 연결의 공통 표준. N×M 커넥터 문제를 N+M으로.

3가지 프리미티브

  • Tools — 모델이 하는 행동(쓰기 측). 호스트 설정에 따라 사용자가 승인/거부.
  • Resources — 모델이 읽는 데이터(파일·레코드·문서).
  • Prompts — 특정 작업을 표준화하는 재사용 템플릿.

전송은 로컬 stdio와 원격 Streamable HTTP(SSE), 와이어 포맷은 JSON-RPC 2.0. 원격 인증은 OAuth 2.1(PKCE). MCP는 API를 대체하지 않고 그 위의 발견·호출 계층이다.

2026 타임라인

  • 2024-11Anthropic이 MCP 오픈소스로 공개.
  • 2025-03스펙 v2: Streamable HTTP + OAuth 2.1. 같은 날 OpenAI 지원 발표.
  • 2025-11최대 규모 스펙 업데이트: 비동기 Tasks·Elicitation·서버측 에이전트 루프·CIMD.
  • 2025-12MCP가 Linux Foundation 산하 Agentic AI Foundation으로 기증(OpenAI·Block 공동 창립).
  • 2026-01MCP Apps 공개 — 대화형 UI를 붙이는 첫 공식 확장.
  • 2026-032026 로드맵: 엔터프라이즈 준비(감사·게이트웨이·설정 이식성) 우선.
Claude·ChatGPT·Gemini·Copilot·Cursor·VS Code·Zed가 클라이언트로, Slack·GitHub·Salesforce·Stripe·Notion 등에 서버가 있다. Python·TS SDK 합계 월 다운로드 약 9,700만 추정.
07

검증

에이전트에서 가장 모자란 조각. 확률적 출력을 결정적 관문으로 묶는다.

  • 결정적 오라클 — 가능한 곳은 참조 구현·테스트·재현 명령으로 "정답"을 만들고 대조한다. 바이트/수치 일치가 최고의 검증.
  • 환각 차단 — 외부 사실(라이선스·API·동작)은 출처 URL 또는 재현 테스트 없이 설계 근거로 쓰지 않는다. 근거 없는 주장은 가정으로 분리.
  • 관찰/추론/미지 분리 — 결론마다 증거 ID를 달고, 확인 못 한 것은 미지로 남긴다.
  • LLM-as-judge는 보조 — 판정자도 틀린다. 가능하면 결정적 검사를 1순위, 판정 모델은 2순위.
  • 10th Man — 주계획에 구조화된 반론을 강제로 붙여 다양한 시각을 확보(적대적 리뷰를 선택이 아닌 규율로).
